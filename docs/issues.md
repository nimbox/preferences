# Property issues (`PropertyIssue`)

`PropertyIssue` describes a **failure to parse, coerce, or validate a runtime value** against a preference **property** (for example typed input coming from an editor control). Think Zod-like: discriminated unions with a **`code`**, **`path`** to the bad value, a **`message`**, and usually the failing **`input`**.

Schema **shape** mistakes (broken property definitions on the preference tree itself) produce **`Diagnostic`** values from **`validateProperties`**, **not** `PropertyIssue`. Two different pipelines.

---

## Shape

- **Union:** discriminate on **`code`** (see table below).
- **Base [`PropertyIssueBase`](../typescript/packages/preferences/src/generated/issue.ts):** **`path`** and **`message`** are always present; **`input`** optional; **`code`** is optional at the base type but required on concrete variants.
- **`path`:** `IssuePathSegment[]` where **`IssuePathSegment = string | number`** — string segments are object keys, **numbers are array indices** inside nested arrays. Example for the first failing array element under `items`: `[ 'items', 0 ]`.

---

## Variants (`code`)

| `code` | Meaning | Extra fields |
|--------|---------|---------------|
| `too_small` | Below min (numeric value, string length, or array length) | `origin`: `'number' \| 'string' \| 'array'`, `minimum` |
| `too_big` | Above max for the same meanings | `origin`, `maximum` |
| `invalid_type` | Value is not the expected scalar/container kind | `expected` (descriptor string) |
| `invalid_enum` | Value not among allowed literals | `options` (allowed values) |
| `invalid_pattern` | String does not match regex | `pattern` |
| `invalid_json` | Text is not valid JSON for object/array properties | _(none beyond base)_ |

---

## Where issues are emitted

Issues are constructed and returned via **`safeParse`** in [`typescript/packages/preferences/src/utils/parse.ts`](../typescript/packages/preferences/src/utils/parse.ts). On failure:

- **`PropertyError`** wraps **`issues: PropertyIssue[]`** (first issue’s message is used for `Error`).
- Narrowing helpers: **`isPropertyError`**, **`isTooSmallIssue`**, **`isTooBigIssue`**, **`isInvalidTypeIssue`**, **`isInvalidEnumIssue`**, **`isInvalidPatternIssue`**, **`isInvalidJsonIssue`**.

The generated header notes that **`PropertyIssue` replaces the older `ParseIssue` naming** in this codebase.
